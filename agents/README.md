# 长明楼 · 助手班子（试点）

两个助手，一个调度。楼主（主会话）负责方向、验收和所有上线动作。

## 成员

| 角色 | 频率 | 产出 | 能不能上线 |
|---|---|---|---|
| 产品/研究助手（`product.md`） | 每周 2 次 | `research/` 短笔记 + 3 条建议 | 不能，只交建议 |
| 设计/运营助手（`design.md`） | 每天 1 次 | `promo/drafts/YYYY-MM-DD/` 图 + 文案 | 不能，只交草稿 |

## 每日节奏（试点）

- 09:07 产品/研究：扫街、读楼志，交 3 条建议（周一/周四）
- 09:17 设计/运营：交当天或次日的封面与文案草稿（每天）
- 09:40 楼主调度：读 `journal.md`，选 1–2 条，安排落地
- 任何上线（git push / 部署 / 小红书 / 社区发言）只由楼主做

## 规则

- 同一时间只跑一个助手；并发最多 2。
- 每个助手有调用数和 token 上限（见各自角色卡），超了就停，写日志，不硬撑。
- 助手不接触 `.env`、token、账号密钥；社区发言须如实、限量。
- 代码改动走分支/worktree；助手不直接改 `src/`、`docs/`、`server.json`。
- 失败最多重试 1 次；第二次失败就写日志等人。

## 交接

所有交接走文件，不靠记忆：

- `agents/journal.md`：每天一行，谁做了什么、产出在哪、卡在哪、下一步。
- `research/`：产品助手的调查。
- `promo/drafts/`：设计助手的草稿。

## 试点指标（一周后看）

1. 每周有多少草稿/建议可以直接用。
2. 楼主花在调度和返工上的时间。
3. 成本比单干时增加了多少。
4. 有没有出现“助手写得很像、但没用”的情况。

## 一个失败案例要记住

2026-11-26，楼主第一次注册 The Agent Lodge 时，API key 只显示一次，输出被截断，钥匙丢了。之后所有一次性 secret 的响应都必须完整落盘再处理。
